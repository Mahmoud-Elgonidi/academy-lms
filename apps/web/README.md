# Academy LMS portal

The academies' web portal (Next.js 16, App Router), in two parts:

- **The teacher's portal** (phase A, `/teach`): today, the week, lesson reports, marking homework (recordings play in the page), students and their roadmap, trial lessons, my hours (shift proposals with the academy), time off, earnings, performance, notifications, and the live lesson in the browser (LiveKit, or the teacher's outside link).
- **The family's portal** (phase B, `/family`), for students and guardians, in the look of the person signed in, as in the app and the `/my` panel: a student's own stage (kids, middle school, teens) or the classic look for adults and every guardian. The journey (a student's home, and `/family/journey` for everyone: the academy's own curriculum as islands and stations, the missions to do now, the stars, the week's chest, the egg and the games on each lesson; see `src/components/journey` below), lessons (cancelling after seeing what the policy will do, turning down a substitute, rating a lesson that took place; kids do none of these), the roadmap and the teacher's reports, homework (handed in as words, a voice recording made in the browser, or a picture or PDF; practice in a game plays from the journey), money (what is owed, paid on the academy's own gateway page or by hand with the receipt sent for the academy to confirm; invoices with their tax document; lessons left; the classic look only), notifications, and the hifz map (`/family/hifz`, from the journey's card once the learner has pages on it: every page of the mushaf by part in its strength, and today's review, each page recited into the browser's microphone and checked word by word while the academy has the check on, or recited from memory, uncovered and graded). A guardian with several children picks whose pages they see.

Both portals stay current by themselves (see "Live" below). Staff keep the back office at `/admin`.

It talks only to the API (`/api/v1`, [`packages/openapi/openapi.json`](../../packages/openapi/openapi.json)), as the Flutter app does, and calls the same Actions through it.

## Run it

```bash
# The API with the demo data (apps/api): docker compose up at the root, or
#   composer migrate && php artisan db:seed && php artisan serve
cd apps/web
npm ci
ACADEMY=demo API_INTERNAL_URL=http://127.0.0.1:8000 npm run build
ACADEMY=demo API_INTERNAL_URL=http://127.0.0.1:8000 npm run start   # http://localhost:3000
```

`npm run dev` works the same way. Sign in at http://localhost:3000/ar with `password` as:

- `khaled@demo.test`, a teacher (a report waiting, a recorded homework to mark, a lesson now and then);
- `ziad.guardian@demo.test`, a guardian (an overdue invoice, lessons to cancel or rate), or `yousef.guardian@demo.test`;
- `yousef@demo.test` (kids), `ziad@demo.test` (middle school), `maryam@demo.test` (teen), students in their own looks, each with their journey as home.

Or sign in with a code: it goes to Mailpit (http://localhost:8025) or `apps/api/storage/logs/laravel.log`.

| Setting | What it is |
|---|---|
| `API_INTERNAL_URL` | where the portal's server reaches Laravel: `http://web:8080` in the production stack, `http://127.0.0.1:8000` on a laptop |
| `ACADEMY` | a laptop only: the academy's slug, sent as `X-Academy` (on a server, the host decides, as for the panels) |

## How it is built

| Where | What is there |
|---|---|
| `src/proxy.ts` | Next's proxy (it was middleware): a page needs the session cookie, except signing in; then next-intl keeps `/ar` or `/en` in the path |
| `src/lib/api/server.ts` | The API from the server only (`server-only`): `get` for pages (401 → sign in again, 403/404 → not found, anything else → the error page), `send` for Server Actions (the API's RFC 7807 words and field errors back to the form). Each call carries the token from the httpOnly cookie, `Accept-Language`, `X-Timezone` (the browser's zone, from a cookie the page writes), and the page's host as `X-Forwarded-Host`. Paths are typed from the OpenAPI document (`schema.ts`): a path or method the API no longer has fails `npm run typecheck` |
| `src/lib/teach/types.ts`, `src/lib/family/types.ts` | What the teacher and family endpoints answer, as the pages read it |
| `src/lib/family` | `context.ts`: the learners, the look of the person signed in (`viewer_stage`) and whose pages they are (the `lms_learner` cookie, else the first); `rules.ts`: what a look allows (money only in the classic look; no cancelling or rating for kids); `nav-items.ts`: each look's places and phone tabs (`nav.{stage}` in messages: kids رحلتي · حصصي · كلّم مدرسك · المزيد, middle school رحلتي · حصصي · الرسايل · المزيد, teens رحلتي · حصصي · الواجبات · التقارير · المزيد, guardians and adults الرئيسية · الحصص · الرحلة · الفلوس · المزيد); `targets.ts`: where a notification opens (the journey, its games and missions open `/family/journey`) |
| `src/app/[locale]/sign-in` | Signing in by code (to an email or number) or password, as Server Actions, then the authenticator's code (`auth/two-factor`) for an account with two-step sign-in on (`lib/two-factor.ts`; a back-office role that must still set it up goes to `/admin`); the token goes into an httpOnly, `SameSite=Lax` cookie (`Secure` behind https) and never reaches the page's scripts. Teachers go to `/teach`, students and guardians to `/family`, staff to `/admin`. Under the form, the academy's own privacy notice and terms (`/privacy`, `/terms` on its host: Laravel's, which the web part serves) |
| `src/app/[locale]/teach` | The teacher's pages (server components) and `actions.ts` (every write: a report, a mark, a trial assessment, a shift proposal and its messages, time off). After a write the page refreshes from the API |
| `src/app/[locale]/family` | The family's pages, wrapped in the look (`layout.tsx`: a `data-stage` frame with the stage's fonts and corners, the academy's colours either way), and `actions.ts` (choosing the learner, cancelling with an idempotency key, turning down a substitute, rating, handing in as multipart, opening the week's chest with an idempotency key, cheering, paying, a guardian agreeing to or withdrawing consent to a child's account on `privacy`) |
| `src/lib/actions/shared.ts` | Writes both portals make: a seat in a lesson, notifications read |
| `src/lib/live.ts`, `src/lib/live-server.ts`, `src/components/live-refresh.tsx`, `src/app/bff/realtime/auth` | Live pages (see "Live") |
| `src/app/bff` | The portal's own routes: `session-ended` (forgets a refused token, then sign in again) and `submissions/{id}/file` (a handed-in file or recording, streamed through with the person's token; the API checks it is theirs to see; seeking passes `Range` on) |
| `src/components` | `ui.tsx` (the small kit), `icons.tsx` (our own line icons), `inbox.tsx`, `handed.tsx` (what was handed in), `roadmap-view.tsx`, `teach/*` (shell and navigation, lesson card, report editor, marking, week view and shift editor, time off, classroom), `family/*` (shell, navigation and learner switch, the classic home with the journey's card, lesson card and its dialogs, hand-in with the browser's recorder, paying, cheering) |
| `src/app/[locale]/family/journey`, `src/components/journey`, `src/lib/journey` | The journey (docs/architecture/02, section 18), from `GET learning/journey/map`, the same answer the app and `/my` draw: `screen.tsx` picks the look (`lib/journey/journey.ts`: `lookOf`), a child's islands (`kids.tsx`: the course's levels as islands drawn by their art's key, an island opened by zooming in with its lessons as a path of stops, a stop's sheet with its missions and games, the missions strip, the egg and the chest), middle school's levels (`middle.tsx`: the stars as a bar to the next rank, each level a path, the race against yourself on a lesson), the calm list for teens, adults and everyone in the calm style (`calm.tsx`), and a guardian's look at their child (`guardian.tsx`: the level, missions, the last lesson's stars, the chest's progress, the games' limits and glance, cheering, playing together). The plain style has no stars, chest, egg or games. `?homework=` starts that homework's practice; `/family/games` and `/family/challenges` lead here; it refreshes on `lessons`, `homework` and `practice` and at the moments the clock alone changes it (`journeyMoments`) |
| `src/app/[locale]/family/hifz`, `src/components/hifz`, `src/lib/hifz` | The hifz map (`GET learning/hifz`): the parts as rows of pages in their strength (`map.tsx`, the academy's colours from `lib/hifz/hifz.ts`), the counts and the legend, today's review, and a page (`[page]`): recited (`review.tsx`, `lib/recorder`, five minutes; `?recitation=` is the one just sent, "listening" until the `hifz` signal brings its check, shown word by word with `components/recited-words.tsx`, as the teacher's marking does) or, with the check off or unable to hear it, recited from memory, uncovered and graded (forgot, hard, good, easy; one idempotency key per press). The journey and the classic home carry today's review as a card (`card.tsx`) while the journey's `hifz` is there. The teacher's student page has the same map read only, the last two weeks' reviews, saying what the student knows (parts, surahs found by name or number, pages, how well) and taking pages off (`teacher.tsx`, `components/teach/hifz-forms.tsx`) |
| `src/components/games`, `src/lib/games`, `src/app/[locale]/family/games/album` | The games around the journey: a round plays in `<iframe sandbox="allow-scripts">` (`round.tsx`, `lib/games/player.ts`: only the frame's own messages, answers only for the round's items) from `/bff/games/{version}`, which serves the game's page on the portal's own origin with the API's own headers (its sandbox policy; `next.config.ts` leaves that route out of the portal's set); its result, hatching (an egg every 12 of the journey's stars, `POST games/hatch` on the third tap) and naming, the album, a guardian's limits and glance. The drawings (`lib/games/art.ts`, `components/games/*.css`, `components/journey/journey.css`) and the sound (`lib/games/sound.ts`) are ports of `shared::games.*` and the panel's styles: change them together. Starting a round on a station or for a homework, finishing it (one idempotency key per round), hatching, naming a creature, the buddy and a guardian's limits are Server Actions in `games/actions.ts` |
| `messages/{ar,en}.json` | Every word; Arabic is Egyptian, as on the panels and in the app |
| `src/app/globals.css` | Tailwind 4 tokens from the academy's branding (`GET /branding`): its colours as CSS variables on `<html>`, tints mixed from them, its corners and fonts; each stage's look (`[data-stage]`: Baloo Bhaijaan 2 for kids, Rubik for middle school, Plex for teens, from `src/fonts`, OFL). Motion (`.appear`, `.stagger`, `.lift`, `.bar-fill`, `.bob`, `.pop`, `.nudge`) only when the person allows motion |

Times are shown as the API writes them (`LocalTime.label`, or the wall clock in `local`); calendar days (a week, a month) are written in UTC so a day stays the same day. The portal never converts zones.

## Live

A page refreshes itself when something it shows changes elsewhere: a lesson booked, moved or cancelled (also from the phone), homework given, handed in or marked, a message arrived or read, a payment settled. The frame (both shells) holds one socket to Reverb, as the panels do:

- `GET /v1/realtime` (in `lib/live-server.ts`, with the unread count for the badge) says where to listen and the person's own channel (`user.{id}`); the socket goes to the page's own host unless the API names another, so on a server it is `wss://<academy host>/app/<key>`, passed to Reverb by the web part.
- The subscription is signed through `/bff/realtime/auth`, which calls `POST /v1/realtime/auth` with the token from the cookie; the page never holds the token, and the API refuses anyone else's channel.
- `components/live-refresh.tsx`: `LiveRefresh` listens for `lessons.changed`, `homework.changed`, `inbox.changed`, `payments.changed`, `practice.changed` (a round, a creature or a limit; with the other two, what the journey shows), `hifz.changed` (a page reviewed, marked, or recited and then heard) and the rest of `SIGNALS` (no data) and the relay's `resync`, then calls `router.refresh()`, which keeps what is being typed. A hidden tab refreshes when it is looked at again; without a socket, or with the relay quiet for 2.5 minutes, a slow timer (a minute) takes over. `RefreshAt` refreshes at the moments the clock alone changes a page (a lesson's room opening, starting, closing; the week's chest closing on the journey), as the panels' `data-live-next` does.

Locally, run Reverb and the relay next to the API (`php artisan reverb:start --port=8080`, `php artisan live:relay`); without them the pages still work and refresh every minute.

## Check it

```bash
npm run lint
npm run typecheck
npm test                 # unit (vitest): days and zones, safe redirects, notification targets, form problems, each look's places and what it allows, the journey's reckoning (looks, stations, homework practice, the sea's layout, its moments), the hifz map (colours, legend, today's review, pages typed as a list, surahs found by name), the live socket and its timers
npm run api:types        # after the API changes (composer openapi), then commit src/lib/api/schema.ts
npx playwright test      # end to end against the running portal and API with the demo data (playwright.config.ts)
E2E_LIVE=1 npx playwright test   # also the live test, with Reverb and the relay running
```

Before the specs, the global setup (`e2e/global-setup.ts`) runs the API's `E2eResetSeeder` (`php artisan db:seed --class=E2eResetSeeder` in `apps/api`, never in production, the demo academy's demo accounts only), which puts back what the tests use up: the week's chests opened, cheers, ratings, an egg to hatch, rounds left open and the guardian's play time and night lock, a receipt left waiting (turned down; an extra lesson sold when nothing is owed), Ziad's homework to hand in and to mark, lessons ahead to cancel, and the lessons and homework since the demo was seeded, as the sweepers would have had them. What depends on the moment a test runs is done when it asks, through `php artisan tinker`: a lesson whose room is open now, on its teacher's outside link (`E2eResetSeeder::lessonNow`, found or booked), and the academy approving a receipt (`approveProof`, through `ApprovePaymentProof`, as the back office would). So no test skips for want of data, at any hour: run them with the API's environment (its `DB_DATABASE` and the rest, which artisan reads), or point `E2E_API_DIR` at another `apps/api` and `E2E_ARTISAN` at another way in (`docker compose exec -T api php artisan`); `E2E_RESET=0` leaves the data alone. Every test also fails on a page that went wrong (a refused script, a console error, an uncaught one, a 5xx, a missing file); the `desktop` project takes each look's pages again at 1366px.

The end-to-end tests sign in (password, code, staff, a refused token, the privacy notice and terms under the portal's and every panel's sign-in), then as Khaled: every page at phone width with no sideways scroll and no message key showing, in Arabic and in English, the week back and forth, a report refused without ratings and then sent with homework, a recording that plays through the portal and a mark, someone else's file refused and an address with no such record not found, time off asked for and withdrawn, a draft of new hours with a message to the academy then withdrawn, the class page opening the lesson's outside link, a ticket to the academy and a safeguarding concern. Then the family: as Ziad's guardian every page at phone width in both languages, the classic tabs, what cancelling would do (and keeping the lesson), a lesson cancelled, a rating, paying on the gateway's page, a transfer receipt sent (refused without the file first), approved by the academy and the invoice paid, the invoice's tax document, the teacher's reports without the academy's own notes, a cheer, a ticket and a concern, his child's journey with the play time and the night lock; as Yousef (kids) the journey as home (the egg hatched and named, the island they are on, a stop's sheet, a round in the sandboxed frame through the game's bridge, the week's chest), a concern with one big button, no money, cancelling or rating, and old links leading to the journey; as Ziad (middle school) his levels and a race on a lesson, going into the lesson on now, homework handed in in words and (with `E2E_LIVE=1`) the teacher's mark arriving on his open page without a reload, the teacher marking it in another browser; as Maryam (a teen) the calm journey and homework handed in by playing. Then every look again at desktop width. They change the demo data; the reset puts back what they use up, and CI runs them on a fresh demo (`.github/workflows/web.yml`).

## On the server

The portal is built into the one production image (`apps/api/Dockerfile.prod`, a Node stage) and runs as its own part, `portal` (`infra/deploy/compose.yml`). The web part passes it `/ar`, `/en`, `/_next` and `/bff`, and a browser opening the bare address goes to `/ar`; the portal calls the API back through the web part, so the academy is the host's. See [`infra/deploy/README.md`](../../infra/deploy/README.md).
