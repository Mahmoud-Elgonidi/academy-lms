# Academy LMS API

Laravel 13 modular monolith: the REST API, the Filament back office and (later) the queue workers for the Academy LMS.
The architecture is in [`docs/architecture`](../../docs/architecture/README.md).

## What's here so far

| Module | What it does |
|---|---|
| `modules/SharedKernel` | Tenancy (`TenantContext`, `BelongsToTenant`, fail-closed RLS helpers, tenant carried into queued jobs), local time (`ViewerTimezone`, `LocalTimePresenter`, `LocalTimeResolver` for summer-time edges), back-office abilities, RFC 7807 errors, `ar`/`en` locale |
| `modules/Platform` | Academies and their domains; resolves the academy from host, slug or id. **Branding**: name, logo, colours, fonts and corners; five built-in templates, custom looks saved as the academy's own templates; `GET /api/v1/branding` |
| `modules/Identity` | Users (per academy), fixed roles mapped to abilities, Sanctum tokens that carry their academy, login / me / logout, per-user preferences, **My settings** page |
| `modules/Communication` | Notifications. Modules declare templates (`NotificationsApi::define`, wording in their own lang files) and send by template key; each person gets the message in their language and time zone, in their inbox and on the outside channels the academy has on and they want: email (Mailpit under docker compose), WhatsApp (Meta Cloud API, one approved template) and push (FCM HTTP v1), both written to the log locally. Per-category choices and quiet hours are Identity preferences (on "My settings" and the API); WhatsApp and push wait out quiet hours unless urgent (`communication:sweep` releases them). Deliveries go through the `notifications` queue with retries. Screens: the **bell** in both panels, **Message log** (resend), **Message templates** (academy wording, channel switches). API: `/api/v1/notifications`, `/api/v1/notifications/preferences`, `/api/v1/devices` |
| `modules/Catalog` | Subjects (levels and categories come later) |
| `modules/People` | Guardian ↔ student links; teacher profiles (gender, languages, dialect, accepting new students / trials, contract hours) and the subjects they teach; **student profiles** (birth date, and the look the academy chose) giving each student their `LearnerStage`: kids (under 12), middle (12–14), teen (15–18), classic (adults, unknown, and every guardian). `FamilyView::stage()` gives the look of the person signed in |
| `modules/Curriculum` | Programs per subject, versions (draft → published → retired; one published per program) and a tree of levels, units and lessons with a weight, the sessions a lesson usually takes and its mastery rule ("mastered" once, or two scores of 4+). Published lessons are never deleted: progress points at them. Screen: **Curricula** (the program list and a builder: add, edit, reorder, publish) |
| `modules/Credits` | The credit ledger in **minutes**: accounts, lots that expire (paid, makeup, bonus…), one reservation per session, append-only entries with idempotency keys. Reserve / consume / release (refund or a 30-day makeup lot) / expire (`credits:expire`, hourly); `CreditBalanceLow` at the renewal mark (makeup minutes aside) |
| `modules/Enrollment` | The learning agreement (student, subject, teacher, from when): `pending_payment` → `active` on the first payment, teacher assignments and status history, and the program it follows, pinned to its published version (set on enrolment when the subject has one program; `CurriculumAttached`). Its screens live in Scheduling, which owns the actions on them |
| `modules/Billing` | Price regions, block plans with a price per region, billing accounts (payer: guardian or student), subscriptions, invoices with gapless numbers and VAT (inclusive or added), manual payments. Paying an invoice grants the block's minutes in the same transaction; the renewal invoice goes out by itself on `CreditBalanceLow`. Screens: **Invoices** (due / overdue / paid, record payment, void, printable invoice) and **Plans and prices** (with regions and tax settings). **Online payments** (the academy is the merchant, on its own gateway accounts): Stripe Checkout, Moyasar invoices (mada, Apple Pay, STC Pay), Tap charges (KNET, BENEFIT), and a demo gateway with its own page outside production. `PaymentGateway` adapters on the HTTP client; keys encrypted; a webhook per account at `/webhooks/payments/{academy}/{account}` into an inbox (each event once); a payment is recorded only when the gateway itself says it is paid (`SettleCheckout`, one payment per checkout), on the payer's return, the webhook or `billing:sweep`. Every invoice message carries the payer's signed pay link (`/pay/invoice/…`, no sign-in); **Pay now** on `/my/account`; **Settings › Online payments** for the owner and accountant |
| `modules/Scheduling` | Sessions, participants (double-booking refused by an exclusion constraint), the session log, attendance deadlines (`scheduling:sweep`, every minute) and the **live board** with its actions. **Shifts**: versioned weekly schedules (one in force per teacher, exclusion constraint), teacher proposals with counter-offers, comments, notice rules and the impact on booked students; teacher API under `/api/v1/teacher/shifts`. **Find a teacher**: availability from the schedule in force each day (DST-safe) minus bookings and holds, week-by-week coverage, suggested patterns, 10-minute holds, then an **enrolment** (or, in trial mode, one free trial lesson in the next two weeks with a teacher who gives trials, ranked by trial conversion; sales may book it, and the family is sent their own link) (`EnrollStudent`: enrollment + credit account + subscription + first invoice + weekly times + sessions, in one transaction). **Weekly times** (`recurring_slots`, on the teacher's clock, exclusion constraint per teacher) become sessions over a rolling horizon (`scheduling:materialize`, nightly); sessions are funded from credit oldest first, and closing a session consumes, refunds or turns its minutes into makeup credit. **Policy**: versioned numbers (`policy_versions`) and the default rule table as a pure engine (`Domain\Policy`); cancel and reschedule by who asked and the notice, a per-block quota, managers' waivers, every decision recorded with its version; unpaid enrolled sessions cancelled a day ahead (in `scheduling:sweep`); makeups booked from makeup credit only; moving an enrollment to another teacher. Screens: **Enrolled students** and the **student account** (cancel, move, makeup, change teacher), **Settings › Cancellation policy** |
| `modules/Learning` | After the lesson. `SessionFinalized` opens a **report** (completed) or an **absence note** (student absent), due 12 hours after the end; `learning:sweep` (every 5 minutes) marks overdue reports and missed homework. The report starts from **today's plan** (the first lesson not mastered, the next once it had its sessions, and reviews that are due) and records an outcome and a score per lesson, two ratings, notes for the family and internal notes, and optional **homework** (text, file or voice recording, on the private disk). A **projector** replays the reports through the mastery rules into `enrollment_progress` (with spaced review: 7, 14, 28… days) and `enrollment_positions` (where the student is, %, pace, expected finish). APIs: `/api/v1/teacher/reports`, `/api/v1/teacher/homework`, and for students and guardians `/api/v1/learning/*` (roadmap, reports without internal notes, homework hand-in, file download). Screens: **Reports** follow-up (overdue / in time / to review / reviewed), the **curriculum and progress** section of the student account, and the **teacher area** at `/teach` |
| `modules/Evaluation` | Lesson ratings and teacher KPIs. **Ratings**: the student or a guardian gives a lesson that took place in the last 14 days 1–5 stars, quick words and a comment (one per person, changeable) from the stars under it on `/my/lessons` (a `scheduling::family.lesson-card` render hook) or from their own signed link (`/rate/{lesson}`, no sign-in) in "how was the lesson?", sent after the first lesson of each week (`SessionFinalized` → `LessonRatingDue`); 3 stars or fewer reach whoever reviews performance. **KPIs** (`TeacherKpis`, last 90 days, read from lessons, attendance, reports, homework and ratings each time): punctuality and average lateness (the policy's late threshold), absence, late cancellation, time taught, leaving early, reports on time, homework marked within 48h, a Bayesian rating (C = 10), and trial conversion through Scheduling's `TrialConversionRates`; each against its target with a minimum sample. A reviewer takes a lesson out of a teacher's numbers with a reason (`kpi_exclusions`). Screens: **Teacher performance** (every teacher against the targets) and a page per teacher (what moved the numbers, ratings with names, take a lesson out), and **My performance** in the teacher area (ratings without names) |
| `modules/Payroll` | Teachers' pay. **Rate cards** (one currency each; a price per hour, paid by the minute, or per lesson, for a subject and kind of lesson or any; the closest line wins; one default card, a teacher on one card at a time). **Ledger** (`teacher_earnings`, append-only, held by a trigger): `AccrueLessonPay` brings a lesson's line in step whenever Scheduling decides, cancels or sends a lesson back for review (`SessionFinalized`, `SessionCancelled`, `SessionFlaggedForReview`), at the share of pay the policy recorded (`decision.teacher_pay_pct`), for whoever taught it; a change is a reversal plus a new line, a line keeps the price it was written at, and a lesson with no price stays "unpriced" until it is priced. **Months** on the academy's clock, closed in order once over (`payroll_periods`; the database refuses lines for a closed month, so later lines go to the first open one); each teacher hears their total (`PayrollMonthClosed`). Bonuses and deductions with a reason, taken back by a reversal. **Export**: the month as an .xlsx (summary, lessons, bonuses and deductions; right to left in Arabic). Screens: **Payroll** (the month, close, export, bonus or deduction, recalculate), a **statement** per teacher, **Teacher rates** in Settings, and **My earnings** in the teacher area |
| `modules/Import` | Bringing an academy's sheets in (xlsx, or csv in UTF-8 or Windows Arabic, up to 2,000 rows): **teachers** (account by email or number, profile, subjects; a missing subject is added; an existing teacher is updated), **families** (a student a row; guardians found by number or email so siblings share one; a child without contact gets a managed account under them), **schedules** (through Scheduling's `ScheduleImport`: an active enrollment, weekly times on the teacher's, the student's or a named clock, lessons ahead, the lessons left as the opening balance, and with a plan `BillingApi::adopt`, so the first invoice is the next block's). Columns map themselves by Arabic or English titles; the **dry run** imports the whole file in one transaction that is rolled back, each row in its own savepoint, so every row says what it would do; the import commits the rows that can go in and lists the rest with the reason (downloadable). New accounts get a **welcome** (`PeopleImported`) with their own signed link to Identity's set-password page. Screen: **Import data** in Settings (owner and admin), with a template per kind and the history |
| `modules/Classroom` | The live lesson. A `VideoProvider` per academy (`classroom_settings`): **LiveKit** (access tokens signed here, rooms through its Twirp room service, room name `{academy}_{lesson}`) or each teacher's **outside link** (Zoom, Meet). The classroom opens 10 minutes before the lesson and closes 10 after it; teacher and student publish, a guardian takes the student's seat, a supervisor joins hidden. LiveKit webhooks (`POST /webhooks/livekit`, signed, deduplicated in `provider_webhook_inbox`) and `classroom:reconcile` (every minute, against the room's participant list) write attendance through Scheduling's `AttendanceApi` into `attendance_segments`; taught minutes are the overlap of teacher and student inside the lesson. The **class page** `/class/{lesson}` (device check, audio-only, screen share, reconnect, today's plan beside the video for the teacher) takes a signed per-person link from the reminder and "join now" messages, so students and guardians need no account on the web. API: `POST /api/v1/lessons/{id}/join` (a ticket for the apps). Screens: **My lessons today** in the teacher area (and the outside link), **Settings › Classroom**, and "observe" / "send the link again" on the live board |
| `modules/Crm` | Leads and trial lessons, on top of everything (nothing depends on it). A **lead**: the contact (a parent, or the adult learner), a WhatsApp number in E.164 (one open lead per number), country and time zone, the learner, the subject and the hours that suit them on their clock, the source with UTM, an owner from sales, and a stage (new → contacted → trial booked → attended → assessed → won, or lost with a reason) moved mostly by other modules' events. `PrepareLearner` gives the learner (and a child's parent) a passwordless account only when a trial or an enrolment needs one, so the trial is an ordinary session and the family joins from their own signed link. The CRM follows `TrialLessonBooked`, `SessionRescheduled`, `SessionCancelled`, `SessionFinalized` (attended: the teacher is asked to assess; not held: back to sales) and `EnrollmentCreated` (won). Trial conversion per teacher (`TrialConversion`, last 6 months, from 3 attended trials) implements Scheduling's `TrialConversionRates`, a weight of 10 in a trial search. Screens: **Leads** (a column per stage, the last 30 days at a glance, search and filters), the **lead page** (contact, trials and assessments, the timeline with calls and notes; book a trial or enrol, which open Find a teacher filled in), and **Trial lessons** in the teacher area (assess: level, plan, lessons a week, notes) |
| Web areas | Three Filament panels, each module adding its screens through its own plugin. **`/admin`**: staff. **`/teach`**: teachers. Screens: today's lessons, **My week**, **My students** (roadmap, last report, homework to mark, a page per student), reports, homework, **My hours** (the week in force; propose, save a draft, answer the academy, accept a counter-offer, withdraw; the same Actions as the teacher API), **My time off** (whole days or hours on their clock, with the lessons it touches counted first; follow the answer and the cover). Back office: **Teacher time off** (approve or reject, record leave for a teacher, and cover each lesson with a substitute from the matching engine or a makeup; uncovered lessons are cancelled an hour before as the academy's doing) and **Academy holidays** (days on the academy's clock: lessons cancelled under rule 15 with the credit's validity extended, one message per person, none generated there), and **Clock changes** (the DST planner, `scheduling:dst` daily: each weekly lesson of the next 45 days next to the same one a week before on the student's clock; where only the student's hour moves, a notice with before, after and until when; families told 14 and 2 days before; keep the teacher's time or, if the teacher is free, the student's, one row or many; and moving a teacher's weekly lessons by the same minutes for some days, all or nothing). **`/my`**: students and guardians (`User::canAccessPanel`). A guardian switches between children; the choice is kept per session by People's `FamilyView`, which every family screen reads. Home cards: next lessons with the way in, progress, homework, last report, lessons left, money owed. Screens: **Lessons** (cancel under the policy, its outcome said in plain words), **Progress** (roadmap), **Reports** (no internal notes), **Homework** (text, a file, or a voice recording made in the browser), **Balance & invoices** (the payer's invoices only). **A student's own area takes the look of their stage**: the home shows the roadmap and where they are on it (Learning's `JourneyQuery`: stars, points and rank, the lesson streak, badges, milestones, the pace and the expected finish, all from the reports and homework). Kids get an adventure map (islands and stops), middle school worlds and stages, a rank and badges, secondary school a plan with milestones and a goal date. People's family plugin adds the stage's font (self-hosted in `public/fonts/stages`, OFL), its shapes over the academy's colours, and a tab bar on phones; screens pick their labels and visibility by stage, and **motion** fitting each stage over the shared motion layer every panel loads (`shared::motion.*`: pages slide in, cards follow, bars fill, numbers count up, confetti for a new star, rank or badge; transform and opacity only, nothing for reduced motion) and the shared frame (`shared::chrome.*`: the side menu as a card with a greeting by the viewer's time of day, icons in chips and the open page as a pill; page changes as View Transitions where the old page lifts away and the pill slides to the new item; a see-through top bar; a livelier sign-in page) (a child sees only their journey, lessons and homework, and leaves cancelling to their guardian; money only for whoever pays) |
| Live updates (`SharedKernel\Realtime`) | No polling anywhere. Table triggers raise `pg_notify('lms_live', '{topic}:{id}')`, delivered on commit, with repeats in one transaction folded into one. Topics: `board:{academy}` from lessons, participants and the session log; `lessons:{teacher}` from a lesson's time, status or teacher; `inbox:{user}` from notifications. **`live:relay`** listens and folds bursts (at most one signal a second per key). Each module maps its topic to a data-less broadcast (`LiveSignals::on`): `BoardChanged` on `private-academy.{id}.board` (that academy, `ViewLiveBoard`), and `TeacherLessonsChanged` / `InboxChanged` on the person's own `private-user.{id}`. It also sends "alive" every minute and "resync" on start on the public `lms.live`. Pages: Echo on every panel page (`EnableBrowserEcho`), and the shared `LmsLive.watch()` refreshes a component on its signal and at the next moment the clock alone changes it (`data-live-next`; for the board, `BoardClassifier::nextChange`). It falls back to its old timer while there is no connection or the relay is quiet. Live: the **live board**, the **bell** (plus a refresh on opening when the list is over a minute old), and **My lessons today** |
| `app/` | Composition only: `ResolveTenant`, the academy and teacher panel providers, `academy:create` |

## The back office

The quickest way, from the repository root (Docker only, nothing else to install):

```sh
docker compose up        # then http://localhost:8000/admin, owner@demo.test / password
docker compose exec api composer demo     # a fresh evening of demo sessions
```

After a `git pull` there is nothing to do (the updates that add the live classroom and live board updates are the exception: restart `docker compose up` once so `livekit`, Reverb on port 8080 and `live:relay` start): a running container notices within seconds and runs `infra/docker/api/sync.sh` again (packages when `composer.json` or `composer.lock` changed, new migrations, and the demo data rebuilt when `database/demo-version` changed); the log says `Up to date.` When it is not running, `docker compose up` does the same on start. Use `--build` only when the `Dockerfile` changes.

For live screens outside docker, run `php artisan reverb:start` and `php artisan live:relay` next to `php artisan serve` (with `BROADCAST_CONNECTION=reverb`; without them live screens fall back to their timers).

Or with PHP 8.3 and Composer on your machine (services from `docker compose up -d postgres redis mailpit livekit`; LiveKit's webhooks then miss the API, which runs outside docker, and `classroom:reconcile` fills attendance in from the room list within a minute):

```sh
# .env: PLATFORM_DOMAIN=localhost (browsers send *.localhost to 127.0.0.1)
php artisan filament:assets && php artisan storage:link
composer demo             # fresh database + academy "demo" with an evening of sessions around now
php artisan serve
php artisan schedule:work # optional: runs the attendance sweeper every minute
```

Open http://demo.localhost:8000/admin and sign in as `owner@demo.test` / `password` (or `scheduler@demo.test`, `accountant@demo.test`).
With `PLATFORM_DEV_ACADEMY=demo` in `.env`, plain http://localhost:8000/admin works too (local environment only; some browsers do not resolve `*.localhost`).

## Running it locally

Requirements: PHP 8.3+, Composer, PostgreSQL 16+ and Redis (or `docker compose up -d` from the repo root).

```sh
# 1. Database roles + databases (skip if you use docker compose; it does this for you)
psql -U postgres -v ON_ERROR_STOP=1 -v db=lms -v owner_password=owner -v app_password=app -v platform_password=platform -f database/setup/roles.sql
psql -U postgres -v ON_ERROR_STOP=1 -v db=lms_test -v owner_password=owner -v app_password=app -v platform_password=platform -f database/setup/roles.sql

# 2. App
composer install
cp .env.example .env && php artisan key:generate
composer migrate          # = php artisan migrate --database=pgsql_owner
php artisan db:seed       # academy "demo" + one user per role, password "password"
php artisan serve
```

Try it:

```sh
curl -X POST localhost:8000/api/v1/auth/login -H 'X-Academy: demo' -H 'Accept: application/json' \
     -d login=teacher@demo.test -d password=password -d device_name=curl
curl localhost:8000/api/v1/me -H "Authorization: Bearer <token>" -H 'Accept-Language: ar' -H 'X-Timezone: Asia/Dubai'
```

New academy: `php artisan academy:create noor --name-ar="أكاديمية النور" --name-en="Noor Academy" --currency=SAR --timezone=Asia/Riyadh --owner-email=owner@noor.test`

## Tests

```sh
composer test     # Pest, against the lms_test database with the real roles
composer lint     # Pint
```

Feature tests use real Postgres with RLS on, not SQLite: the app connects as `lms_app`, so a missing tenant really returns no rows.

## Rules that keep tenants apart

1. **Three database roles.** The app runs as `lms_app` (RLS applies). Migrations run as `lms_owner` (`composer migrate`); plain `php artisan migrate` fails on purpose. Only Platform code may use `pgsql_platform` (BYPASSRLS); an arch test enforces it.
2. **Every tenant table:** `$table->tenant()`, `$table->tenantKey()`, then `TenantTable::enableRls('table')` in the migration, and `use BelongsToTenant` on the model.
3. **References between tenant tables** use `$table->tenantForeign('user_id', 'users')`, never a plain foreign key: foreign-key checks bypass RLS.
4. **The academy is resolved before auth.** From the bearer token (source of truth), else the host (`{slug}.PLATFORM_DOMAIN` or a verified custom domain), else the `X-Academy` header. A token sent to another academy gets 403.
5. **Modules talk through `Contracts/`.** `tests/Arch` fails the build otherwise.
6. **The back office resolves the academy the same way.** `ResolveTenant` runs first in the panel's middleware, before the session loads the user, and again on every Livewire request.
